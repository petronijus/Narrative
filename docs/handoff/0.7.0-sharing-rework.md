# 0.7.0 — Sharing rework — deploy notes

Closes the usability gap from M10. Now invite collaborators by email
instead of by opaque Google `sub`, list pending invites, show names in
the dialog and presence bubbles.

## Before pushing the redeploy

### 1) DB migration

`0013_users_and_invites.sql` runs automatically via `migrate.js`. It
creates two tables (`users`, `deck_invites`) and backfills `users` from
`sessions` so the dialog renders correctly for accounts that signed in
before this deploy.

No env var changes.

### 2) Rsync + deploy

## What to verify after redeploy

1. Open `https://narrative.example.com/` → land on deck list. Your own
   row in the `users` table should already exist (backfilled from the
   active session).
2. Open the share dialog on any deck you own. Your name should appear
   in the "People with access" list (not the 21-digit sub).
3. Type a colleague's email in the invite field. Two paths:
   - **They've signed in before** → 200 response, instant grant, they
     appear in the list with name + email + role.
   - **They haven't** → 201 response, row appears under "Pending
     invites". After they log in for the first time the invite is
     consumed → they get a real permissions row.
4. Cancel a pending invite. The row disappears.
5. Have two people open the same folder in different tabs. The bubbles
   on each deck tile show real initials (first letter of name or
   email), tooltip shows `Name (email) is editing`.

## DB schema

```sql
CREATE TABLE users (
  sub TEXT PRIMARY KEY,
  email TEXT NOT NULL,
  name TEXT,
  picture_url TEXT,
  first_seen_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_seen_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- Case-insensitive email uniqueness (a Google sub may legitimately
-- change email — last writer wins).
CREATE UNIQUE INDEX users_email_lower_uniq ON users (LOWER(email));

CREATE TABLE deck_invites (
  id TEXT PRIMARY KEY,                     -- nanoid(12), also the URL token
  deck_id TEXT NOT NULL REFERENCES decks(id) ON DELETE CASCADE,
  email TEXT NOT NULL,                     -- stored lower-case
  role deck_role NOT NULL,
  invited_by_sub TEXT NOT NULL,
  invited_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  expires_at TIMESTAMPTZ NOT NULL,         -- default 30 days
  accepted_at TIMESTAMPTZ,
  accepted_by_sub TEXT
);
-- One pending invite per (deck, email)
CREATE UNIQUE INDEX deck_invites_deck_email_pending_uniq
  ON deck_invites (deck_id, LOWER(email))
  WHERE accepted_at IS NULL;
```

## API contract changes

| Before (0.6.x)                                               | After (0.7.0)                                                           |
| ------------------------------------------------------------ | ----------------------------------------------------------------------- |
| `POST /decks/:id/permissions {userId,role}`                  | `POST /decks/:id/permissions {email,role}` → 200 granted \| 201 pending |
| `GET /decks/:id/permissions → [{userId,role,grantedAt}]`     | `... → [{userId,role,grantedAt,email,name}]`                            |
| —                                                            | `GET /decks/:id/invites → [{id,email,role,invitedAt,expiresAt}]`        |
| —                                                            | `DELETE /decks/:id/invites/:inviteId → 204`                             |
| `GET /folders/:id/active-editors → [{deckId,userIds:[sub]}]` | `... → [{deckId,users:[{userId,email,name}]}]`                          |

These are all owner-only endpoints (`requireDeckRole('owner')`).

unused but harmless. Drop manually if you want a clean state:


## Future work

  invitee out-of-band that they've been invited. Adding actual email
  delivery is a follow-up. The invite row already has a token that
  can be embedded in an `/i/<id>` URL.
- **Avatar pictures**: `users.picture_url` is recorded but not yet
  rendered. ShareDialog and ActiveEditorsBubbles could swap initials
  for the Google profile image.
- **User search**: invite field could autocomplete from `users` table
  for known colleagues.
