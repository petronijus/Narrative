## Scope

First-class `TableObject` in the slide model, end-to-end:

- **Insert from toolbar**: 10×10 grid picker (Word / PowerPoint /
  LibreImpress style). Hover sizes, click commits + drops the table
  on the active slide.
- **Edit inline**: per-cell rich text via the existing Y.Text
  pipeline (HTMLText renderer), per-cell padding / fill / borders,
  per-table defaults.
- **Borders**: flat segment-keyed model (one stroke per grid line).
  Outer-rim alignment-inside trick + corner patches give clean
  Excel-style corners. Mixed widths / colours don't double-paint
  because each line is a single value.
- **Inspector parity**: tables get the same `IdentitySection` /
  `PositionSection` / `TypographySection` / `AnimationsSection` /
  `LayersPanel` the shape inspector renders. Folder text-style
  presets bind to tables via `TableDefaults`.
- **Scope-aware writes**: Typography + Appearance edits dispatch
  through range → active cell → defaults. Inspector reads the
  effective style at the same scope so what you see is what the
  renderer will paint.
- **Gestures**: tap on a selected table = cell-select mode; drag =
  move the table; drag inside cell-active mode = range select.
  Enter in a cell inserts a paragraph (matches text-box behaviour);
  Cmd/Ctrl+Enter still jumps to the next row.
- **Fill**: solid / linear gradient / radial gradient / image fill on
  tables. Routed through the shared `FillBody` + procedural-texture
  cache the shape inspector uses (so a 50-cell table-wide gradient
  paints one canvas per drag tick instead of fifty).

## Non-goals (deferred)

- Table styling presets (Office's "Medium Style 2 — Accent 1" etc.).
- Charts inside cells.
- Per-cell binding to a folder text-style preset (table-level only).
- Smooth taper at mixed-width border transitions — same artifact
  Excel / PowerPoint / Keynote show; uniform widths give the
  cleanest look.

## Architecture

### Data model (`packages/shared/src/slide.ts`)

```ts
interface TableObject extends BaseSlideObject {
  type: 'table'
  colWidths: number[] // proportional, sum scaled to .width
  rowHeights: number[] // proportional, sum scaled to .height
  rows: TableCell[][] // [r][c]; merge pointers carry mergeOriginR/C
  defaults: TableDefaults // fontFamily, fontSize, weight, italic, underline,
  // lineHeight, letterSpacing, textTransform, color,
  // align, vAlign, fill, fillAlpha, fillStyle?, border,
  // padding, textStyleId?, textStyleOverrides?,
  // paragraphSpaceBefore?, paragraphSpaceAfter?
  borderSegments?: {
    // flat sparse map — see "Border model" below
    [key: TableBorderSegmentKey]: TableBorderStyle
  }
}

interface TableCell {
  text: string | Y.Text // promoted to Y.Text on first mutation
  // cell overrides — missing fields inherit from table.defaults
  fontSize?
  fontWeight?
  italic?
  underline?
  lineHeight?
  letterSpacing?
  textTransform?
  color?
  align?
  vAlign?
  fill?
  fillAlpha?
  fillStyle?
  border?
  padding?
  // merge cells
  gridSpan?
  rowSpan?
  mergeOriginR?
  mergeOriginC?
}
```

### Border model — flat segment map

Every grid line in a table is **one** segment with **one** stroke spec.
Key format:

- `h:<row>:<col>` — horizontal segment, `row ∈ [0, R]` (R+1 rows of
  lines), `col ∈ [0, C)`. `h:0:*` is the table's outer top;
  `h:R:*` is the outer bottom.
- `v:<row>:<col>` — vertical, `row ∈ [0, R)`, `col ∈ [0, C]`.
  `v:*:0` is the outer left; `v:*:C` is the outer right.

`getEffectiveBorderSegment(table, key)` reads from `borderSegments`
first, falls back to deriving from the legacy `cell.border.X` fields
for decks created before this change (right / lower cell wins on
shared edges — deterministic).

The legacy per-cell `top/right/bottom/left` model had a fundamental
ambiguity: every shared line was owned by two cells and could carry
two different values that would double-paint at different widths
or colours. No amount of mirror-write or auto-clear plumbing fixed
it — replacement with a flat segment map did.

### Renderer (`apps/web/src/renderer/objectRenderers/tableRenderer.ts`)

Three passes per rebuild:

1. **`paintCellFills`** — per-cell fill `Graphics` keyed by
   `cellFillKey(style, w, h)`. Early-outs when nothing visually
   changed; gradient textures are shared via the
   `ResourceManager` procedural cache.
2. **`paintBorders`** — iterates the `(R+1) × C` horizontal grid +
   `R × (C+1)` vertical grid. One stroke per line, no double-paint.
   Outer-rim strokes are shifted INSIDE the table by half their
   width so nothing bulges past the visible bounds (Keynote-style
   alignment).
3. **`paintCornerPatches`** — at each grid intersection, paints a
   filled square sized to the thickest adjacent stroke's width and
   coloured by that stroke. Eliminates butt-cap notches and gives
   mixed-width corners a unified colour (Excel-style: thicker wins).

`applyPatch` has three dispatch paths:

- **Fast** — transform / opacity / filter / `borderSegments` only.
  No cell reconcile, no fill repaint.
- **Mid** — `defaults` changed but only fill-related fields. Calls
  `paintCellFills` alone; skips both `paintBorders` and the
  HTMLText reconcile. Keeps gradient-stop drag responsive on
  multi-cell tables.
- **Full rebuild** — anything else structural.

### Mutations (`packages/slide-model/src/tableMutations.ts`)

- `buildTable(opts)` / `addTable(ctx, opts)` — pure construction.
- `insertTableRow / Col` / `deleteTableRow / Col` — splice the row /
  col + shift segment keys via `shiftBorderSegments`.
- `mergeTableCells / splitTableCell` — set / clear
  `gridSpan` + `rowSpan` + `mergeOriginR/C` pointers.
- `setTableCellStyle / setRangeCellStyle / setTableDefaultsPatch` —
  granular style writes.
- `setRangeBorderPreset(ctx, id, range, preset, edgeSpec)` —
  writes the preset's target segment keys to `borderSegments`.
  Preset → segment key set via `segmentsForPreset(preset, range)`.
  `preset === 'none'` writes width 0 so the renderer's skip-guard
  suppresses the `defaults.border` fallback on those lines.
- `setTableBorderSegment(ctx, id, key, value)` — direct single
  segment write (for future per-segment UI).

### Inspector (`apps/web/src/ui/TableInspector.tsx`)

Shared `Section` chrome wraps every block: Identity, Position,
Structure (Rows / Columns count steppers — granular insert /
delete lives in the canvas right-click menu), Typography,
Appearance, Padding, Border, Animations, Layers.

Typography + Appearance read + write scope-aware:

- **Read**: `targetCell = topLeft(range) ?? active ?? null`.
  Synthetic `TextObject` / `RectangleObject` shim falls through
  `cell.X ?? defaults.X` so inputs show the effective style under
  the cursor.
- **Write**: dispatch through `patchRange` (when range) →
  `patchCell` (when active) → `patchDefault` (when neither).
  Defaults-only fields like `fontFamily` always write to defaults.
  Preset binding (`textStyleId`) is table-level only — applying a
  preset writes every preset field to defaults regardless of
  selection scope.

Border preset UX:

- Clicking a preset _selects_ it (highlights the icon) and primes
  the Style / Color / Width inputs with the existing segment values
  for that preset's target keys. Doesn't mutate.
- Adjusting any input restamps the active preset with the new
  value, normalising every targeted segment.
- Mixed indicator when the preset's target segments aren't uniform.

### Toolbar grid picker (`apps/web/src/ui/Toolbar.tsx`)

Click the Table button → 10×10 grid popover → hover to size →
click any cell to commit. Calls `addTable(objectsCtx, { x: 100,
y: 100, width: cols × 120, height: rows × 60, rows, cols })`,
selects the new table, flips `activeTool` back to Select.

The `K` shortcut still activates the legacy click-to-place flow
(`activeTool = 'table'` → click on canvas to create a default 3×3).

## Migration

No deck migration required. Existing decks with the legacy per-cell
`cell.border` data render unchanged via the
`getEffectiveBorderSegment` fallback. The new model takes over for
any cell whose border is touched after the upgrade.

## Deploy notes

**Hotfix during deploy**: `jszip`, `fast-xml-parser`, `pptxgenjs`
were declared in `apps/server/devDependencies` but imported at
runtime by `apps/server/src/pptx/parser.ts` + `export.ts`. The
production image runs `pnpm install --prod --ignore-scripts` which
excludes devDeps, so the server crashlooped with
`ERR_MODULE_NOT_FOUND` for `jszip`. Fix: promoted the three to
regular dependencies. Worth adding a CI check that runs the
prod-install path against the server image so this class of bug
doesn't bite future deploys.
